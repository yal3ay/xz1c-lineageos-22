# Bug 反馈

这是系统管家的可选功能，默认关闭。仅在用户逐份查看并确认后，才提交有限技术字段到维护者后台。

## 编译前准备

`src/main/java/org/lineageos/zramstatus/FeedbackProvider.java` 是私有生成文件，不能进入 Git。公开源码只保留 `.example` 模板和生成工具。

在编译机建立权限为0600的私有配置（不要放在源码仓库），仅包含一行 `INBOX_UPLOAD_TOKEN=实际令牌`。此令牌应与服务器私有环境文件一致；不要包含管理密码，也不要在命令行参数、报告或聊天里写出令牌。

```sh
python3 apps/ZramStatus/tools/provision-feedback.py \
  --config ~/.config/xz1c-feedback/client.env --source apps/ZramStatus
/home/joey/build.sh codex-system-feedback ZramStatus
```

上面的第一个命令在 `vendor/sony/lilac` 仓库根目录执行。必须在编译开始前生成，编译期间不能改源码。

安装包必须包含上传凭据才能提交，因此持有安装包的人可能提取这个共用的、仅能上传的令牌。它不是用户身份凭证，不能读取或删除后台报告。后台还必须保留字段校验、大小限制、频率限制和独立管理密码；不能把共用令牌当作防滥用的唯一保障。

## 完整系统集成

产品配置把 `xz1c-bug-feedback.xml` 复制到 `/system/etc/sysconfig/`。它允许受保护的错误记录事件唤起已由用户启用的反馈组件，避免常驻进程或周期查询。

仅更新系统管家安装包无法增加已启动系统的事件允许配置，且新增的错误记录读取权限可能不会在旧系统上自动授予。因此界面会关闭自动收集入口，并提示需要维护者提供的完整系统更新；仍然可以手动创建、查看并提交报告。

完整系统首次启动后，须验收读取权限、后台自动事件、主用户过滤、静默通知和默认关闭状态。不能把旧系统上的定向模拟事件测试当成完整系统首启验证。

## 报告内容与诊断

- 手动反馈必须选择应用（也可选系统／不确定）并填写问题描述。上传应用包名、数字版本及可取得的显示版本；描述可包含复现步骤与公开作品链接。
- 主动重现提供最多180秒的可见记录服务，保存所选应用、版本、描述、内存与亮屏采样、同一窗口内该应用的有限崩溃信息，以及播放诊断。录屏是独立可选项，使用 Android 的屏幕捕获授权，不录声音。
- 播放诊断只读取预先列出的媒体日志标签，按记录窗口筛选，最多保存48条、合计8192字节；命令有3秒期限与256KiB输出上限。标记选定应用进程与共享媒体进程；共享记录可能来自其他应用，不可直接归因。网络地址会被替换。
- 状态为 captured（已取得）、partial（仅取得部分）、no_matching_records（没有匹配记录）或 unavailable（无法取得）。日志已被系统覆盖、应用不输出信息或权限受限时，不伪造编码、分辨率和错误原因。
- 此功能不清日志、不强停应用、不切换图形设置、不请求管理员权限。报告在本机预览后由用户提交；录屏单独预览与确认。
- 自动崩溃报告继续采用既有有限字段，并默认关闭。新旧报告共用 schema=1；服务器兼容旧客户端。

本机最多20份、有效7天，过期文件下次使用时清理。技术报告上限65536字节；后台最多2000份、保留30天。上传失败不自动重试。安装包内的上传凭据只可提交，后台管理使用不同凭据。

## 服务器协议扩展（2026-10-29）

手动报告新增 application、description、package、app_version_code、app_version_name；旧版只有类别的报告仍可提交。重现报告的 session 可附 playback 对象（status、scope、records、renderer、renderer_32bit），顶层可附 application、description、app_version_name。

技术上限从24576提高到65536字节，服务器与网站入口同步调整。录像仍走既有的带长度前缀二进制入口和独立大小限制，不改变认证和保留规则。

## 验证范围

服务端测试覆盖旧报告、新报告、带诊断的重现记录、字段与大小拒绝、未授权拒绝、重复提交和后台转义。诊断过滤测试使用主机替身验证时间范围、进程标记、去重、地址替换与字节上限；不代替真机日志权限和实际花屏复现验证。
